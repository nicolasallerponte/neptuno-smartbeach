## QuantumLeap Subscriptions

Six subscriptions must be created by `subscriptions/create_subscriptions.py`, one per dynamic entity type. Each subscription is a POST to `http://localhost:1026/ngsi-ld/v1/subscriptions/` with headers `Content-Type: application/ld+json` and `NGSILD-Tenant: smartbeach`.

The notification endpoint for all subscriptions is `http://quantumleap:8668/v2/notify` with `receiverInfo` key `fiware-service` value `smartbeach`.

The six entity types to subscribe are: `SeaConditions`, `WeatherObserved`, `WeatherForecast`, `WeatherAlert`, `WaterQualityObserved`, `WaterQualityPredicted`.

## Data Flow Pipeline

```
Real APIs (MeteoGalicia, INTECMAR, Puertos del Estado, Xunta OpenData)
    ↓ fetched by simulator/meteo_fetcher.py every 10-60 min
simulator/simulator.py (fills gaps with realistic simulated values)
    ↓ PATCH http://localhost:1026/ngsi-ld/v1/entities/{id}/attrs
Orion Context Broker :1026 (stores current state)
    ↓ NGSI-LD subscriptions notify on change
QuantumLeap :8668
    ↓ persists to

    ↓ queried by
Grafana :3003 (dashboards) + ml/train.py (model training)

backend/main.py :8000
    ← queries Orion for current data
    ← queries QuantumLeap for historical data
    ← calls Ollama :11434 for LLM chat with Orion context injected
    → serves frontend/

frontend/ (browser)
    ← Three.js globe (province overview)
    ← Leaflet map (beach detail with heatmap)
    ← Chart.js (time series, predictions)
    ← Chat UI (LLM assistant)
    ← Alerts panel (polling every 30s)
```

## Frontend Structure

Single Page Application with 4 views and no page reloads. Dark theme with colors: background `#0a0f1e`, accent `#7ec8e3`, success `#4ade80`, warning `#facc15`, danger `#f87171`.

**Globe view** (`globe.js`): Three.js r128 sphere centered on A Coruña province. 12 beach markers colored green/yellow/red by current status. Rotatable with mouse. Click on a marker navigates to beach detail view.

**Beach detail view** (`map.js` + `charts.js`): Leaflet map centered on the selected beach with OSM tiles and a heatmap layer showing crowd density. Below the map: 4 Chart.js panels showing sea temperature last 7 days, wave height last 7 days, water quality history (E. coli), and 48h occupation prediction.

**Chat view** (`chat.js`): Text input sends POST to `/api/chat`. Before calling Ollama, the backend fetches current state of all beaches from Orion and injects it as context in the LLM prompt. Response displays with typewriter effect.

**Alerts view** (`alerts.js`): Polls GET `/api/alerts` every 30 seconds. Shows active `WeatherAlert` entities with severity color coding and source badge showing `MLModel`, `IoTSensor`, `CVSystem`, or `CitizenReport`.
